# Skill — barak-fleet-pdf-publisher

ידע תפעולי מלא לסוכן **ברק**. קרא בתחילת כל משימה.

---

## 1. פרוטוקול אימות אישור (חובה — שלב ראשון)

לפני הפקת PDF, ודא **בכתב** מאייל:
1. **מקור מאושר?** — `כן/לא`. אם `לא` → עצור והעלה לאייל.
2. **רמת חתך** — סניף בתוך חטיבה / חטיבה / קבוצה.
3. **מספר גרסה** — `v1.0` למקור, `Rev 2`/`Rev 3` לתיקונים.
4. **ייעוד** — `פנימי` / `פנימי-חסוי` / `חיצוני` / `ארכוב`.
5. **סיווג סימן מים?** — `אין` / `פנימי בלבד` / `חסוי`.

**אם הייעוד חיצוני → דורש אישור נוסף מפורש מאייל לפני הפקה.**

---

## 2. נוסחי Header/Footer קבועים

### Header (בכל עמוד פרט לעמוד שער)
```
[ימין — RTL]                                      [שמאל]
<שם המסמך> — <תקופה> — <רמת חתך>          G1 Group | מערכת ניתוח צי
```
פונט: Tahoma 9, אפור כהה `#404040`. קו תחתי דק.

### Footer (בכל עמוד כולל שער)
```
[ימין — RTL]                                      [שמאל]
גרסה <v1.0> | <2025-05-15 14:30>          עמוד <3> מתוך <12>
```
פונט: Tahoma 9, אפור `#7F7F7F`. קו עליון דק.

### עמוד שער — בנוסף
מתחת לכותרת הראשית:
```
תקופת ניתוח: <DD/MM/YYYY> – <DD/MM/YYYY>
רמת חתך:    <תיאור>
גרסה:        <v1.0> | <תאריך הפקה>
מקור הנתונים: <שם קובץ Excel של גל>
```

---

## 3. מוסכמת שמות קבצים

```
<YYYYMMDD-HHMM>-fleet-<סוג>-<חתך>-<תקופה>-v<גרסה>.pdf
```

| שדה | ערכים |
|------|-------|
| `<סוג>` | `report` (דוח Word→PDF) / `analysis` (Excel→PDF) / `presentation` (PPT→PDF) / `summary` (תקציר) |
| `<חתך>` | `group` / `division-<שם>` / `branch-<שם>` |
| `<תקופה>` | `2025Q2` / `2025` / `202504-202506` |
| `<גרסה>` | `1.0` / `1.1` / `2.0` |

**דוגמאות:**
- `20250515-1430-fleet-report-group-2025Q2-v1.0.pdf`
- `20250515-1430-fleet-presentation-division-north-2025-v2.0.pdf`

## 4. פרוטוקול גרסאות

| מקרה | גרסה |
|------|------|
| הפקה ראשונה | `v1.0` |
| תיקון קוסמטי (טעות הקלדה, פורמט) | `v1.1` |
| תיקון נתון או תוספת תוכן | `v2.0` |
| גרסה מתוקנת לאחר משוב הנהלה | `Rev 2`, `Rev 3` בנוסף ל-v |

תמיד שמור את הגרסה הקודמת ב-`output/archive/` ולא מחק.

## 5. דרישות טכניות ל-PDF

| מאפיין | דרישה |
|--------|--------|
| תקן | PDF 1.7 או PDF/A-2b לארכוב ארוך טווח |
| פונטים | **Embedded** (חובה לעברית — בלעדיהם הטקסט יישבר במחשבים ללא Tahoma) |
| RTL | טקסט עברית מוצג מימין לשמאל, מספור עמודים תקין |
| רזולוציית גרפיקה | 300 DPI מינימום לתמונות, גרפים וקטוריים |
| גודל קובץ | יעד < 10MB לדוח טיפוסי. אם גדול יותר — בצע אופטימיזציה לתמונות |
| מטא-נתונים | כותר, מחבר ("מערכת ניתוח צי — G1 Group"), נושא, מילות מפתח, תאריך |
| Bookmarks | חובה — לפי הפרקים של הדוח (תוכן עניינים פעיל) |
| אבטחה | הגנת עריכה (לא העתקה) למסמכים חיצוניים. סיסמא — לפי בקשת אייל בלבד |

## 6. סימני מים (Watermarks)

לפי הסיווג:

| סיווג | סימן מים | צבע | זווית |
|--------|-----------|------|--------|
| אין | — | — | — |
| פנימי בלבד | "פנימי בלבד — G1 Group" | אפור בהיר 30% | 45° |
| חסוי | "חסוי — אין להפיץ" | אדום בהיר 30% | 45° |

הוסף בכל עמוד, מאחורי הטקסט (background layer).

---

## 7. רשימת בקרת איכות (חובה לפני שמירה סופית)

פתח את ה-PDF המופק וודא:

- [ ] עברית מוצגת תקין בכל עמוד (לא ריבועים, לא הופך תווים).
- [ ] RTL — שורות מתחילות מימין.
- [ ] מספור עמודים תקין ועקבי.
- [ ] Header ו-Footer קיימים בכל עמוד (פרט לשער).
- [ ] חותמת זמן ומספר גרסה ב-Footer כל עמוד.
- [ ] רמת חתך מצוינת בעמוד השער וב-Header.
- [ ] גרפים וטבלאות לא נחתכים בין עמודים.
- [ ] Bookmarks (תוכן עניינים פעיל) קיימים ומקושרים.
- [ ] פונטים מוטבעים (בדוק ב-File→Properties→Fonts → כל הפונטים `Embedded` או `Embedded Subset`).
- [ ] מטא-נתונים מלאים (Title, Author, Subject).
- [ ] סימן מים נוכח (אם סיווג דורש).
- [ ] גודל קובץ סביר (< 10MB ברירת מחדל).
- [ ] שם הקובץ עוקב למוסכמה.

## 8. טיפול בבעיות נפוצות

| בעיה | פתרון |
|------|--------|
| עברית הופכת בכיוון (חיבור אותיות מצד שמאל) | ודא שהמרה משתמשת ב-PDF engine שתומך BIDI. השתמש ב-`anthropic-skills:hebrew-document-generator` (reportlab/WeasyPrint עם תמיכת bidi) |
| פונט לא מוטבע — טקסט מתעוות במחשבים אחרים | הוסף את Tahoma כ-embedded subset בעת ההמרה |
| גרף נחתך בין עמודים | חזור לסוכן המקור (גל/אירית) ובקש Page Break לפני הגרף |
| Header/Footer לא מופיע בעמוד הראשון | זה רצוי — בעמוד השער אין Header. ודא ש-Footer כן מופיע |
| קובץ כבד מדי | אופטימיזציית תמונות ל-150 DPI במקום 300 (לעותקים פנימיים) |

## 9. כלי עבודה

- השתמש בסקיל **`anthropic-skills:pdf`** ליצירה והמרות.
- לעברית RTL מקצועית — **`anthropic-skills:hebrew-document-generator`** (יודע לטפל ב-bidi נכון).
- שמור ל-`output/`. עותק קודם → `output/archive/`.
